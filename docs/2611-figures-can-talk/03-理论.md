## 3.4 工作底稿



知识库里对底稿的规范写得很具体：**三类底稿（主表、辅表、测试底稿）+ 三种表达（审计符号、注释、相互索引）**。下面按这三类各给一个示例，数字是为示范拟的（甲公司 2025 年报、单位万元）。

## 先看骨架：索引是一棵树

```
A 总体        A1 审计计划  A2 整体趋势变动分析
D 损益        D1 营业收入(主表) → D1-1 收入明细(辅表) → D1-1-1 收入抽查(测试底稿)
E 长期资产    E1 固定资产(主表) → E1-1 新增明细(辅表) → E1-1-1 新增抽查(测试底稿)
                                → E1-2 折旧合理性(测试底稿)
K 权益/其他   K1 …
```

先做整体趋势变动分析，再做主表，最后做辅表，这就是书里说的“自顶而下”（E1 是华山大弟子，E1-1 是他外套，E1-1-1 是外套上的扣子）。

## 示例 C：测试底稿 E1-1-1 新增固定资产抽查（audit test work paper）

| 项目       | 内容                                                                                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 测试目的   | 存在性、估值（折旧起算时点）、权属                                                                                                                              |
| 方法与逻辑 | 以新增明细为总体，按金额降序＋随机抽样；检查合同、发票、验收单、付款凭证，确认资产真实存在并已投入使用；按投产日期复算折旧起算月份                              |
| 总体与抽样 | 总体 28 笔 / 170 万元；选取 8 笔 / 126 万元（占 74%），其中单笔≥10 万元的全部选取（5 笔），其余随机 3 笔；样本明细见上表（准则要求列明样本，以便他人重新测试） |
| 检查结果   | 7 笔无异常；1 笔（M-07，120 万元）9 月投产、10 月起计提折旧，少提折旧 80 万元                                                                                   |
| 结论与处理 | 已提出调整 AJ-03，调整后未更正错报为零；该科目剩余风险可接受                                                                                                    |

> 测试底稿不一定有数据表，但这五项——**目的、方法与逻辑、总体范围、抽样方法、结果与结论**——不能缺。

## 示例 D：审计符号图例（放在项目底稿最前面）

| 符号 | 含义           | 说明                                         |
| ---- | -------------- | -------------------------------------------- |
| √   | 加总已复核     | 通用工作，全所统一                           |
| G/L  | 核对至总账     | 通用                                         |
| S/L  | 核对至明细账   | 通用                                         |
| CF   | 已函证         | 通用                                         |
| →   | 索引至其他底稿 | 表示“这两个数已核对一致，工作见另一张底稿” |
| ⚠   | 待跟进         | 项目专用，须在图例中说明                     |

两条规则：**通用符号全所统一，不必每次解释；项目专用符号必须做图例**。而且要记住一句：符号不是装饰，标上就代表你真做了这项工作——电子底稿里最容易犯的错，是把去年的符号一起拷过来。

## 附：两种表达方式的高下（书里的旅馆例子）

```
× 100×8+150×7+200×5=2850（元）
```

| 房价（元/天）  | 间数         | 金额（元）      |
| -------------- | ------------ | --------------- |
| 100            | 8            | 800             |
| 150            | 7            | 1,050           |
| 200            | 5            | 1,000           |
| **合计** | **20** | **2,850** |

同样的数字，右边这种“数据库结构”式的写法，别人才能复查你的每一步。审计底稿要的就是这个。

## 注释写法对照

**× 讲故事（要避免）**：我们先是查了台账，又找了设备部老王，跑了三趟车间，翻了两年前的验收单，最后才终于发现……

**√ 开门见山、一句话说出结尾**：抽查 8 笔新增设备，1 笔（M-07，原值 120 万元）于 2025 年 9 月投产但自 10 月起计提折旧，少提折旧 80 万元，已提出审计调整（AJ-03，详见 E1-1-1）。

写什么、不写什么：写背景、写热点（如收入确认）、写你对这个科目的“预期”以及实际是否符合预期、从 CEAVOP 各角度谈；**不写**审计计划里已经说过的和常识性的东西。
